# week-01

## 当前实现与 hermes 对比

1. 因为当前代码体量很小，所以把整体循环逻辑和相关方法都放进一个 agent.py 文件里。然后把 agent 通用行为之外的实际调用过程抽象到 client.py 文件做分离。当功能增多时可以参考 hermes 现在的做法，把 session、turn、context、tool_execution 等功能拆成独立的模块。

2. 目前工具执行仅做了顺序执行，没有做并行。顺序执行适用于现在简单的逻辑。当后续需要支持一些 IO 等待时间较长的任务时，例如网络搜索、文件读取，并行工具执行能带来更好的时间收益。

3. 出于简单，目前没有对工具 id 做检查。这是因为目前接入的 dpsk 模型总是能返回正确的模型 id。如果扩展，需要考虑到各模型的行为并不总是一样。
