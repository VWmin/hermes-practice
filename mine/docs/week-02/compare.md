# week-02

## 与 hermes 实现对比

1. 当前实现参考了 hermes 的自动发现并注册工具实现：扫描特定目录并加载模块，使工具自注册到 registry。

2. 当前实现对工具名错误、工具参数错误处理比较简单，直接将错误消息交给模型，而 hermes 中会尝试重发请求来修复问题。本实现中除了循环次数的限制其他情况基本不中止 turn，而 hermes 会在发现存在连续无效工具或参数内容存在截断时停止。好处是不需要关心错误细节，依赖模型的能力来从错误中恢复。缺点是有些错误并不能靠发送错误信息解决，比如网络问题。

3. hermes 中会一次对一批 tool_calls 处理工具名和参数，本实现中逐个处理：先判定工具存在、然后确保输入格式为字符串、然后将字符串解析为参数字典、尽力将参数值转换为 schema 中要求类型、最后使用 handler 调用工具。本实现的原则是保持简单。hermes 中批量处理再执行能够同时适应串行和并行执行方式，同时能够将工具执行接到其他实现形式上。
