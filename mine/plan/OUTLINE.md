# Hermes 学习大纲与进度管理

制定日期：2026-09-23。

适用基础：熟悉 Python 和 tool calling，重点学习 Agent 架构。
源码基线：本地 `hermes-agent/`，提交 `550d74c6`，项目声明版本 `0.21.4`。
节奏假设：每周 6–8 小时，持续 6 周；以阶段验收为准，不以读完文件数量为准。

## 1. 学习路线与最终目标

推荐采用“按能力纵向打通”的路线：提出一个架构问题，追踪 Hermes 的真实调用路径，独立写出简化实现，再对照它的取舍。

三种路线的取舍：

| 路线 | 优点 | 主要代价 |
| --- | --- | --- |
| 按能力纵向打通（本计划） | 每阶段都有可运行成果，能把架构与问题对应起来 | 需要主动控制阅读范围 |
| 先系统读完主要模块再实现 | 前期覆盖面较广 | 容易陷入兼容层与产品细节，反馈较慢 |
| 直接裁剪 Hermes | 较快获得丰富功能 | 难判断哪些设计是必要的，不利于从零理解 |

练习场景暂定为“本地学习助手”：读取自己的学习笔记、按关键词查找内容、整理学习记录、记住个人偏好。这个场景能自然覆盖循环、工具、会话、记忆和上下文管理；以后更换用途时，主要替换工具。

**预计第 3 阶段的 v0.1：** 一个命令行助手，能连续对话、使用本地工具、保存和恢复会话、在失败或预算耗尽时明确停止。

**预计第 6 阶段的 v0.2：** 在 v0.1 上支持显式长期记忆、受限上下文、一个可复用的学习流程，并经过真实任务验证。

第一轮范围：单用户、单进程、单模型供应商、同步执行、工具串行调度。使用模型 SDK 即可，核心循环自己写。多 Agent、消息网关、浏览器、MCP、插件市场、桌面 UI、多供应商回退留作后续选修。

## 4. 提交、评估与推进规则

### 你提交什么

随时告诉助手“完成了哪些内容、产出在哪里、怎么验证、还有哪些疑问”。可以提交局部成果，不必等整周完成。建议使用以下格式；也可以直接自然语言描述：

```text
本次进度：第几周，完成了什么
笔记路径：
源码路径：
运行或验证方法及结果：
希望重点评估的问题：
```

没有涉及的项目可以省略。产出以实际文件、运行结果和你的解释为依据。

### 助手如何评估

1. 先读取本大纲、当前周计划及已有评估记录，再查看你指定的产出。
2. 将产出逐项映射到当前周验收标准；检查理解是否准确、实现行为是否正确、证据是否充分。
3. 对源码先阅读，再按需执行与本周范围相关的验证；需要付费 API 或外部副作用的步骤先明确说明，已有运行证据可用于评估并标明来源。
4. 给出有文件位置或运行证据支撑的意见，区分“本周必须补齐”与“后续可改进”。单纯的风格偏好或未来功能不阻止本周通过。
5. 证据不足时明确列出缺项；不能因文件存在、代码量足够或你说读完了而直接判定完成。仅凭产出不能判断理解时，提出针对性问题。
6. 默认进行评估和辅导，保留由你实现核心逻辑的学习过程；你明确要求修改代码时再协助修改。

每次评估写入当前周计划末尾，包含日期、审阅范围、证据来源、逐项结论、建议和下一步。按时间追加，保留之前的意见及后续修正结果。

### 三种评估结论

- **部分完成**：已有内容得到验证，继续剩余任务。
- **待补充或修正**：存在明确的理解问题、行为缺陷或证据缺口；列出最小补齐清单。
- **本周完成**：当前周全部必需验收项有充分证据，不要求完成选修或下一周内容。

部分提交只更新已验证项目，不提前勾选未审阅内容。尚未通过时，保持当前周计划并给出下一步建议，不创建下一周详细计划。

**本周通过后**，助手在同一次评估中更新本周状态和大纲，保存评估结论，再依据实际产出、薄弱点和已有实现制定下一周详细计划。上一周的计划与记录保留，作为学习档案。每次最多开启下一周，不提前展开所有剩余周。

## 5. 学习方法

一次约 2 小时：15 分钟明确问题与预期行为，30 分钟查文档和源码，50 分钟独立实现，15 分钟验证，10 分钟写对照笔记。

每次只回答一个核心问题。笔记保留五项：

1. 我遇到的问题是什么？
2. Hermes 的调用路径、关键状态和不变量是什么？
3. 我的最小方案是什么？
4. 我暂时省略了哪些机制，什么情况下必须补上？
5. 哪个实验或测试证明我理解了？

优先自己写核心循环和状态转换，再让 AI 做讲解、追问或审查。判断是否学会的标准，是能脱离源码重新解释并实现，而不是复制后能运行。

阅读 Hermes 测试时，如需执行，遵循参考仓库规定使用 `scripts/run_tests.sh` 并只选相关文件；自己的项目独立配置测试。没有必要为了开始学习先安装 Hermes 的全部可选能力或跑完整测试集。

## 6. 后续选修

核心路线完成后，按实际需求选择聊天平台网关、定时复盘、外部检索、MCP 或子 Agent 中的一项。新增能力前先说明它解决了哪一个当前系统无法完成的真实任务。
